## Не забыть, кроме ключей

- **Пароль root на VPS** — он мог уходить в те же руки.
- **SSH-ключ** `id_ed25519_proxy`, если он лежал рядом с проектом.
- **Пароль пользователя `rubl` в PostgreSQL** менять и в базе тоже:
  `ALTER ROLE rubl PASSWORD '<новый>';` — затем то же значение в `.env`.
- **Локальные копии архивов** с боевым `.env` — удалить с диска и из корзины.
- Проверить в YCLIENTS журнал входов на предмет чужих сессий.

## Проверка, что старые ключи мертвы

После замены — убедиться, что прежние действительно отозваны:

```bash
# YCLIENTS: должен вернуть 401/403
curl -s -o /dev/null -w '%{http_code}\n' \
  -H 'Authorization: Bearer <старый_partner>, User <старый_user>' \
  -H 'Accept: application/vnd.yclients.v2+json' \
  https://api.yclients.com/api/v1/company/<company_id>/staff

# DeepSeek: должен вернуть 401
curl -s -o /dev/null -w '%{http_code}\n' \
  -H 'Authorization: Bearer <старый_ключ>' \
  https://api.deepseek.com/v1/models

# Telegram: должен вернуть 401
curl -s -o /dev/null -w '%{http_code}\n' \
  https://api.telegram.org/bot<старый_токен>/getMe
```

Если что-то отвечает `200` — ключ живой, отзыв не сработал.

## Чтобы не повторилось

- `.gitignore` теперь исключает `*.zip` и прочие архивы: в них секрет уезжает
  незаметно для code review — именно так утёк пароль кабинета.
- Секреты в репозиторий не попадают даже «как пример»: в `.env.example`
  только заглушки в угловых скобках.
- Перед публикацией репозитория и перед каждым `git add` на файлах
  конфигурации — прогонять `scripts/check-keys.sh` из сборки v2.
