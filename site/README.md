# Публичный сайт rublbarber.ru

Статическая витрина барбершопа. Сборки нет: это готовые файлы, которые
выкладываются в хранилище как есть.

```
index.html      главная, одностраничник
privacy.html    политика обработки персональных данных
404.html        страница ошибки
sitemap.xml     карта сайта
robots.txt
fonts/          локальные шрифты (woff2) и fonts.css
img/            изображения, видео, превью для мессенджеров
deploy.sh       выкладка в Object Storage
setup-keys.sh   разовая настройка ключей доступа
```

## Главное правило

**У страниц не должно быть запросов к зарубежным доменам.** Разрешены только
`*.yclients.com` (виджет записи) и Яндекс (карта, счётчик).

Сайт переехал из Амстердама именно потому, что перестал открываться из
России. Один сторонний CDN возвращает эту проблему целиком. `deploy.sh`
проверяет это перед каждой выкладкой и не даст выложить нарушение.

Шрифты по этой причине лежат локально в `fonts/`. Подключены в трёх файлах:
`index.html`, `privacy.html`, `404.html` — менять во всех сразу.

## Выкладка

Разово настроить доступ:

```bash
uv tool install awscli
./setup-keys.sh
```

Скрипт спросит идентификатор ключа и секрет, запишет их в отдельный профиль
`rubl` (чужие профили AWS не трогает) и сразу проверит доступ к бакету.

Спрашивает именно скрипт, а не вы подставляете заранее: у bash и zsh разный
синтаксис чтения ввода (`read -s -p` в zsh означает чтение из сопроцесса), и
на этом легко застрять на ровном месте.

Ключ берётся в консоли: Сервисные аккаунты → аккаунт → Создать новый ключ →
Создать статический ключ доступа. Аккаунту достаточно роли `storage.editor`.
**Секрет показывают один раз, в окне создания.** Закрыли окно — восстановить
нельзя, только выпускать новый ключ.

### Почему AWS CLI, а не s3cmd

В имени бакета есть точка, и привычная адресация через поддомен даёт имя
`rublbarber.ru.storage.yandexcloud.net`, которое не покрывается сертификатом
`*.storage.yandexcloud.net`. Нужна адресация через путь:
`storage.yandexcloud.net/rublbarber.ru/...`.

AWS CLI переключается на неё сам, увидев точку в имени. У `s3cmd` это
делается правкой `host_bucket` вручную, и на этом стенде подпись запроса не
сходилась — сервер отвечал `SignatureDoesNotMatch`. Разбираться, чья это
беда, смысла нет: инструмент, который делает верно без уговоров, лучше.

### Как читать отказ

`SignatureDoesNotMatch` Yandex отдаёт и на неверный секрет, и на удалённый
ключ, и на выдуманный — проверено подстановкой заведомо ложных значений.
По тексту эти случаи не различить, так что «ключ точно правильный» эта
ошибка не опровергает и не подтверждает.

Дальше:

```bash
./deploy.sh --dry-run   # посмотреть, что изменится
./deploy.sh             # выложить
```

Скрипт раскладывает кеширование правильно: картинки, видео и шрифты — на год,
HTML — на пять минут. Иначе правки не дойдут до тех, кто уже был на сайте.

В бакет уезжает только перечисленное: `img/`, `fonts/` и файлы `.html`,
`.xml`, `.txt`. Всё остальное, что лежит в этой папке, остаётся дома. Список
разрешённого, а не запрещённого, — потому что при перечислении исключений
новый файл рядом попадает на витрину по умолчанию.

## Размещение

Object Storage в российском регионе, режим статического сайта.

- имя бакета: **ровно** `rublbarber.ru` — совпадает с доменом, переименовать
  бакет нельзя;
- главная страница `index.html`, страница ошибки `404.html`;
- публичный доступ на чтение, лимит объёма на бакет;
- HTTPS: сертификат из Certificate Manager привязывается к бакету — для имён
  с точкой это обязательный шаг;
- `www.rublbarber.ru` — отдельный бакет с переадресацией на основной.

Порядок переключения: сначала проверить сайт на техническом адресе бакета
**с мобильного интернета российского оператора без VPN**, и только потом
переводить домен, заранее уменьшив TTL у регистратора.

## Что осталось — данные от владельца

Искать по слову `ЗАПОЛНИТЬ` в `index.html`:

1. **Часы работы** — сейчас предположение 10:00–22:00 в трёх местах.
2. **Персональные ссылки барберов** — нужны идентификаторы мастеров из YCLIENTS.
3. **Стаж в карточке мастера** — скопирован от другого барбера, фактическая ошибка.
4. **Цены** — взяты из выгрузки YCLIENTS, могли измениться.
5. **Яндекс.Метрика** — счётчика нет. Ставить до переключения домена, иначе
   не с чем будет сравнить посещаемость.
6. **Почтовый индекс** — в разметке организации его нет. Для дома 22к1
   значится 121615, но для корпуса 2 это не проверено.

Ничего из этого не мешает выложить сайт: он уже лучше того, что сейчас
недоступно из России.

## Чего на сайте нет и быть не должно

Форм сбора данных, полей ввода и серверной части. Запись выполняется виджетом
YCLIENTS, данные уходят напрямую в эту систему. Это зафиксировано в
`privacy.html`, и менять поведение без правки политики нельзя.
