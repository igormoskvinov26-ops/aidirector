# Установщик для Windows

Собирает один файл — **`РублЪ-Директор-Установка.exe`**. Человек запускает
его, подтверждает окно UAC и больше ничего не делает: установщик сам ставит
Docker, собирает Директора, поднимает базу и открывает браузер.

## Собрать

```
apt-get install -y nsis
installer/build.sh
```

Полминуты, результат — `РублЪ-Директор-Установка.exe` в корне проекта.
В репозиторий он не попадает (`.gitignore`): внутрь упакован весь исходный
код, и проверить по двоичному файлу, что туда не уехал `.env`, на code
review невозможно. Собирать заново — дешевле, чем хранить.

Сборка идёт на Linux: `makensis` умеет делать exe для Windows, отдельная
машина не нужна.

## Из чего состоит

| Файл | Что делает |
|---|---|
| `installer.nsi` | сам установщик: распаковка, ярлыки, задание планировщика, запись в «Программы и компоненты» |
| `bootstrap.ps1` | всё остальное: Docker, сборка образа, миграции, браузер |
| `build.sh` | собирает груз из файлов под git и вызывает `makensis` |
| `director.ico` | значок — брендовая монета из `site/img/coin-emblem.png` |

Груз собирается **по списку git**, а не по маске файловой системы: так в
установщик заведомо не попадут ни `.env`, ни `.venv`, ни `node_modules`.
`build.sh` дополнительно проверяет, что файла настроек в грузе нет, и
останавливается, если он там оказался.

## Что происходит при установке

1. Распаковка в `C:\ProgramData\RublDirector\app` — там же лежит контекст
   сборки Docker и журнал.
2. Настройки: установщик ищет файл рядом с собой — `настройки.env`, потом
   `.env`, потом `%USERPROFILE%\Downloads\настройки.env`. Нашёл — кладёт как
   `app\.env`.
3. `bootstrap.ps1 -Mode install`:
   * нет Docker → скачивает и ставит в тихом режиме
     (`install --quiet --accept-license --backend=wsl-2 --always-run-service`,
     ключи из документации Docker);
   * запускает Docker Desktop и ждёт, пока `docker info` ответит;
   * ограничивает права на папку: SYSTEM, администраторы и тот, кто ставил.
     Группа «Пользователи» доступ теряет — в `.env` лежат ключи YCLIENTS и
     все пароли;
   * `docker compose up -d --build`, ждёт контейнер, `alembic upgrade head`,
     проверяет `/health`;
   * открывает браузер.
4. Задание планировщика `РублЪ Директор` — при входе в систему поднимает всё
   заново (`-Mode autostart`). Оно же продолжает работу после перезагрузки,
   если её потребовал Docker.
5. Ярлык «Директор» на рабочем столе → `-Mode open`: если Директор отвечает,
   просто открывает браузер; если нет — поднимает и показывает, что мешает.

Код возврата `bootstrap.ps1` установщик разбирает числом, не текстом:
`0` готов, `10` нет настроек, `11` нужна перезагрузка, `12` не поднялся,
`1` исключение. Текст пришлось бы отдавать в какой-то кодировке, и на этом
всё бы и село.

## Чего установщик сделать не может

Две вещи, и обе — не недоработка.

**Права администратора.** Docker Desktop ставит свою службу и включает WSL2;
без повышения прав это невозможно. Поэтому одно окно UAC при запуске
остаётся. Всё, что после него, идёт без вопросов.

**Ключи и пароли.** Придумать токены YCLIENTS установщик не может. Их
приносит файл `настройки.env` — это обычный рабочий `.env`, положенный рядом
с установщиком. Один раз подготовили — дальше установка на любое число
компьютеров идёт вообще без участия человека. Без этого файла Директор
поставится, но не запустится, и установщик прямо об этом скажет.

Побочно: ставить нужно под той учётной записью, под которой человек
работает. Установщик требует прав администратора, и если в окне UAC ввести
чужой логин, ярлык на рабочем столе и задание планировщика достанутся той
учётной записи. На домашнем или салонном компьютере, где человек сам
администратор, этого не случается.

И ещё: если Docker ставился с нуля, Windows может потребовать
перезагрузку. Она тоже не требует действий — после входа в систему задание
планировщика доведёт установку до конца само.

## Что проверено, а что нет

Проверено здесь, на Linux:

* `makensis -WX` собирает без единого предупреждения;
* установщик распаковывается 7-Zip'ом и содержит ровно то, что нужно:
  `app/` с `backend`, `frontend`, `local`, `assets`, `.env.example`,
  `.dockerignore` — и ни одного файла `.env`;
* `bootstrap.ps1` внутри установщика байт в байт совпадает с исходным,
  метка кодировки (BOM) на месте, кириллица цела;
* русские имена файлов (`frontend/src/мастера.tsx`) переживают упаковку;
* `bootstrap.ps1` разбирается парсером PowerShell без ошибок, конструкций
  из PowerShell 7 в нём нет — штатный 5.1 его прочитает;
* `Get-AppPort` и `Test-Settings` проверены на реальных файлах настроек.

**Не проверено:** сам ход установки на живой Windows. Здесь нет ни Windows,
ни Docker, и проверить установку Docker Desktop, задание планировщика и
сборку образа неоткуда. Это первое, что нужно сделать на настоящей машине.

## Локаль при сборке

`build.sh` выставляет `LC_ALL=C.UTF-8`. Без этого `makensis` падает с
segmentation fault, как только доходит до файла с кириллицей в имени.
Проверено 18.09.2026.
