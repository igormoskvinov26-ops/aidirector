## 1. Что это и кто этим пользуется

Пульт — программа для управления салоном. Она работает **на компьютере салона** (Windows), а также на Маке
владельца. Данные берёт из YCLIENTS (CRM салона: записи, клиенты, сотрудники, продажи) и показывает их
владельцу, администратору и мастерам в браузере по адресу `http://127.0.0.1:8000`.

Разделы:

| Раздел | Кому | Что делает |
|---|---|---|
| Смена | админ, владелец | открытие и закрытие смены: показатели дня, приход и уход мастеров, отчёт в Telegram |
| Клиентская база | админ, владелец | вся база клиентов таблицей, очередь обзвона, карточка с исходом звонка, теги, скрипты |
| Журнал обзвона | админ, владелец | каждое нажатие кнопки исхода, счётчики, сверка «записался» с YCLIENTS |
| Пульс базы | владелец | новые, вернувшиеся и потерянные, баланс базы, разрез по мастерам |
| Записи за месяц, Расчёт ЗП | владелец, мастер (только своё) | выручка и зарплата мастеров |
| Финансы, Контроль финансов | владелец | расходы, план-факт, сверка кассы с отчётами банка (эквайринг, СБП) |
| Месячный отчёт | владелец | итоги месяца по мастерам и администраторам, проверка звонков |
| Сторис | владелец | картинки со свободными окнами для Telegram |
| Настройки | владелец | интеграции (YCLIENTS, Telegram, почта, общий сервер), скрипты, теги, фоны, филиалы |

**Роли** (HTTP Basic, `backend/app/main.py`, `main_roles.py`):
- `owner` — всё. Учётная запись «Владелец» (флаг `top`) видит ещё и филиалы, учётная запись «управляющий» — свой филиал;
- `operator` — администратор салона. Доступны только `/api/client-base`, `/api/shift`, `/api/me`, `/api/salon` и
  состояние выгрузки (`OPERATOR_API_PREFIXES`), всё остальное отдаёт 403. Для администратора открывается отдельный
  интерфейс (Смена, Клиентская база, Журнал обзвона). Владелец открывает его по адресу `/#admin`;
- `master` — свой расчёт зарплаты (`MASTER_API_PREFIXES`), строка выбирается по `staff_id` из YCLIENTS.

Администраторов несколько, логин у них один. Кто звонит, администратор выбирает на экране,
и пароля на этот выбор нет (известная слабость, §13).

## 2. Главное ограничение: персональные данные

**Имена и телефоны клиентов хранятся только в базе PostgreSQL на компьютере салона.** Это требование
владельца (152-ФЗ): общий сервер стоит за рубежом. Любое изменение, которое может отправить или
выгрузить имя, телефон, комментарий или заметку, должно сохранять это правило.

Как это обеспечено:

| Куда уходят данные | Что уходит | Где в коде | Чем проверено |
|---|---|---|---|
| Общий сервер (hub) | смены, остатки кассы, строки банка, настройки отчёта, состояние обзвона **по `yclients_id`** (`ПОЛЯ_СОСТОЯНИЯ`), звонки **по `yclients_id`** (`ПОЛЯ_ЗВОНКА`, документ `calls:<месяц>:<номер установки>` — свой у каждого компьютера; журнал показывает звонки других компьютеров рядом со своими, `client_base._звонки_других_компьютеров`), справочник тегов | `services/hub.py` | `tests/test_hub_privacy.py`, `test_tags_scripts.py` |
| Excel-журнал `output/обзвон.xlsx` | дата, время, **ID клиента YCLIENTS**, сегмент, результат, канал, комментарий, кто звонил | `services/call_journal.py`, `COLUMNS` | `tests/test_call_journal.py` |
| Кнопка «Excel» (скачивание журнала) | файл собирается на лету в новом виде, даже если на диске лежит старый | `routes/client_base.py` `/journal`, `call_journal.выгрузка` | `test_call_journal.py` |
| Telegram | отчёты смены: цифры и имена **сотрудников** | `services/shift.py`, `telegram.py` | — |

Старые файлы журнала (с колонками «Клиент», «Телефон») переписываются в новый вид при каждом
запуске (`call_journal.очистить_старые`, вызывается в `lifespan` в `main.py`).

Оговорка для протокола: `yclients_id` — псевдоним. Салон может сопоставить его с человеком через YCLIENTS,
поэтому по закону это всё ещё персональные данные. Полностью снять вопрос можно только сервером в России.

Порт базы наружу не открыт. Приложение слушает только `127.0.0.1` (`BIND_HOST` в compose).
Диск не шифруется, резервных копий базы нет (§13).

## 3. Архитектура

```
 Браузер (React SPA)  ──HTTP Basic──▶  контейнер rubl_director (FastAPI + uvicorn, :8000)
                                          │   ├─ раздаёт собранный фронтенд из /app/static
                                          │   ├─ фоновый цикл выгрузки YCLIENTS (раз в час)
                                          │   ├─ фоновый обмен с hub (раз в 45 с, если настроен)
                                          │   └─ почта IMAP (отчёты банка), Telegram
                                          ▼
                                 контейнер rubl_db (postgres:16-alpine), том rubl_data
                                          (порт наружу не открыт)

  YCLIENTS API  ◀── httpx ──  rubl_director  ── httpx ──▶  hub (VPS, SQLite)
  api.yclients.com                                      https://igor-moskvinov.fvds.ru
```

- **Backend:** Python 3.11+, FastAPI, SQLAlchemy 2 (async, asyncpg), Alembic, pydantic-settings, httpx + tenacity,
  loguru, openpyxl, Pillow. Зависимости закреплены в `backend/uv.lock`, ставятся через `uv sync --frozen`.
- **Frontend:** React 19, Vite, Tailwind v4, TypeScript (strict, `noUnusedLocals`), Recharts, lucide-react.
  Роутинга нет: разделы переключаются состоянием в `App.tsx`, интерфейс администратора включается по `#admin`.
- **Docker:** `local/docker-compose.yml` описывает два сервиса. `local/Dockerfile` **не собирает фронтенд**:
  он копирует готовый `frontend/dist` в `./static`, а при старте выполняет
  `alembic upgrade head && exec uvicorn app.main:app --host 0.0.0.0 --port 8000`.
  Фронтенд собирается при сборке пакета (§8). Причина: на Маке салона `npm ci` зависал внутри Docker.
- **Филиалы:** у каждого филиала своя база PostgreSQL в том же контейнере. Реестр филиалов —
  `output/branches.json`, логика в `services/branches.py`. Ключи интеграций изолированы по филиалам.
- **Общий сервер (hub)** в папке `hub/`: `app.py` на FastAPI с SQLite. API: `GET /v1/health`, `GET /v1/changes`,
  `PUT /v1/doc/{key}`, авторизация через `HUB_TOKEN`. Нужен, чтобы салон и Мак владельца видели одни и те же смены
  и статусы обзвона. Если два компьютера изменили один документ, остаётся версия, пришедшая первой.

  Ключ к YCLIENTS — `yclients_id`.
- **Метрики:** `daily_metrics`, `monthly_metrics`, `plan_targets`, `cost_model`, `daily_segment_snapshots`.
- **Обзвон:** `contact_tasks` (очередь на день), `contact_attempts` (каждое нажатие исхода: админ, время, `was_lost`,

  Поля обзвона на клиенте: `clients.next_contact_at/_note/_by`, `call_status`, `last_call_at/_outcome/_by`,
  `loyalty*`, `do_not_call`, `admin_note`.
- **Смены и деньги:** `shifts`, `shift_employees`, `cash_balances`, `acquiring_rows` (поле `source`: эквайринг или СБП).
- **Служебные:** `sync_runs`, `app_settings` (управляемые настройки и состояния, ключ-значение), `settings_audit`,
  `telegram_settings`, `report_settings`, `monthly_report_snapshots`.

### Миграции

`backend/alembic/versions/0001…0016`. **Все миграции идемпотентны**: они проверяют, есть ли колонка или таблица,
прежде чем создавать. Это нужно, потому что установки салона в прошлом расходились со схемой.
Контейнер выполняет `alembic upgrade head` при каждом старте.

Правила для новой миграции:
1. Пишите её идемпотентной: `inspect` → `if column not in ...`.
2. Добавьте новые колонки и таблицы в список `fix_db.py` (`local/package/`). Это аварийный инструмент `FIX-DB`.
3. Если миграцию не добавить в пакет, сборка остановится: `build_package.py` сверяет число миграций.
4. **Базы филиалов при обновлении не мигрируются.** Миграции для базы филиала выполняются только при создании
   филиала (`branches._миграции`). CMD контейнера мигрирует только главную базу. Если у салона появится второй
   филиал, вызывайте `_миграции` при переключении или при старте для всех баз из `branches.json`.

## 5. Бизнес-правила

Часовой пояс расчётов — `Europe/Moscow`. Клиент определяется по `client_id` YCLIENTS и никогда по имени.

**Смена** — по ТЗ `docs/history/01_TZ_smena_otkrytie_zakrytie.md`, §37 там содержит 18 критических правил.
Главное из них:
- новый клиент — сегодняшний визит первый; повторный — второй; постоянным клиент становится на пятом выполненном визите;
- открытие смены — снимок состояния, закрытие — пересчёт по свежим данным;
- приход и уход мастеров вводятся вручную;
- ошибка YCLIENTS никогда не показывается нулём.

**Сегменты очереди обзвона** (`compute_segment`) строятся по личному ритму клиента. Берётся медиана интервалов между
визитами, r = дни с последнего визита / медиана:

| Код | Название | Условие |
|---|---|---|
| `active` | Активные постоянные | r < 0.90 |
| `due` | Пора записываться | r < 1.15 |
| `risk` | Зона риска | r < 1.50 |
| `late` | Сильно задерживаются | r < 2.00 |
| `lost` | Потерянные | r ≥ 2.00 |

Если ритм нестабилен (меньше 4 визитов, меньше 3 интервалов или разброс больше 35%), применяются пороги 30, 60 и 120 дней.

**Очередь на день** (`refresh_tasks`) включает группы `due`, `risk`, `late`, `lost`. Ещё в неё попадают:
- `callback` — плановый перезвон, приоритет 6;
- `losing` — «Теряем сегодня»: последний визит ровно 60 дней назад и нет записи вперёд, приоритет 8;
- `manual` — клиент, открытый из поиска; такие задачи пересборка не стирает.

Клиент с тегом, у которого стоит `exclude_from_calls`, или с флагом `do_not_call` в очередь не попадает.

**Исходы звонка** (`record_outcome`):

| Исход | Что делает сервер |
|---|---|
| `booked` | Записан. Задача уходит на сверку с YCLIENTS |
| `no_booking` | Без записи |
| `no_answer` | Не дозвонились. Следующий звонок автоматически ставится на завтра |
| `callback` | Перезвонить. Без даты не принимается, сервер отвечает 400 |
| `do_not_call` | Не звонить. Снимает плановую дату |

Каждое нажатие пишется в `contact_attempts` и строкой в Excel-журнал.
`was_lost` = клиент был в группе `lost` в момент звонка. Это основа счётчика «возвращённых».

**Сверка «Записан»** (`monthly_report.verify_pending`): ищется запись того же клиента, созданная после нажатия,
в пределах окна атрибуции (3 дня). Одна запись подтверждает один звонок. Сверка запускается после выгрузки и при
закрытии смены. В журнале колонка «Запись» показывает дату визита этой записи
(`visits.yclients_id == contact_attempts.yclients_record_id`), и строка подсвечивается зелёным.

**Потерянный клиент — три разных определения (известное расхождение):**
- пульс и баланс базы считают потерянным с 61-го дня без визита (`LOST_AFTER_DAYS = 60`, потерян на `+61`);
- отчёт смены и «Теряем сегодня» берут последний визит ровно `сегодня − 60`;
- группа `lost` в очереди считается по ритму (r ≥ 2) или после 120 дней.

Анализ и план выравнивания — в `docs/history/08_TZ_zhiznennyi_cikl_razbor.md`. Решения владельца по нему ещё не приняты.

**Ссылка на клиента в YCLIENTS** (`YCLIENTS_CLIENT_URL`, `ссылка_yclients`): адрес базы филиала на `yclients.ru`
с быстрым поиском по телефону. Телефон подставляется в виде «8» + последние 10 цифр. Адрес дал владелец,
формат взят у него точно.

## 6. Интеграции

### YCLIENTS
- База API: `https://api.yclients.com/api/v1`, заголовки `Authorization: Bearer {partner_token}, User {user_token}`,
  `Accept: application/vnd.yclients.v2+json`.
- Используются эндпойнты: `/company/{id}/staff`, `/clients/{id}` (поиск клиентов), `/records/{id}`,
  `/storages/transactions/{id}`, `/companies?my=1` (доступные токену филиалы), `/staff/schedule`, `/auth`
  (получение пользовательского токена по логину и паролю).
- Ключи: `YCLIENTS_PARTNER_TOKEN` (партнёрский, у разработчика), `YCLIENTS_COMPANY_ID` (2036703 — салон),
  `YCLIENTS_USER_TOKEN` (выдаётся в обмен на логин и пароль сотрудника салона; в кабинете YCLIENTS его не показывают).
- Поля, которые приходят `null`, читаются только через `_словарь`, `_записи`, `_деньги` и `_целое`
  (инцидент 28.09, `docs/history/02_...`).
- Ошибки: `YclientsОтказ` сохраняет `meta.message` из тела ответа и путь запроса.
  При 401 или 403 проверка в Настройках дополнительно показывает список филиалов, доступных токену.

### Telegram
Бот и чат задаются в Настройках → Интеграции. Через Telegram уходят отчёты смены и сторис. «Тестовое сообщение»
отправляется только по кнопке.

### Почта (IMAP)
Из почты забираются отчёты банка (Альфа-Банк: эквайринг и СБП). По умолчанию сервер `imap.yandex.ru`, нужен пароль
приложения. Поток отчёта определяется по содержимому файла, а не по имени. Модуль `mail_acquiring.py` работает
на стандартной библиотеке.

### Общий сервер (hub)
`HUB_URL` (по умолчанию `https://igor-moskvinov.fvds.ru`) и `HUB_TOKEN`. Состав передаваемых полей — см. §2.

## 7. Настройки

Порядок источников: **переменная окружения > значение из интерфейса (база, `app_settings`) > `.env` > пусто.**
Значение, заданное окружением, в интерфейсе показывается с пометкой «задано на сервере» и только для чтения.
В локальной установке `.env` попадает в контейнер через `env_file`, а самого файла внутри нет. Поэтому compose
ставит `RUBL_ENV_FROM_FILE=1`, и всё окружение считается «файлом»: интерфейс его перекрывает
(`config._из_окружения`). До 9.25.1 метки не было, и токен YCLIENTS, сохранённый в интерфейсе, молча не применялся.
Секреты наружу не отдаются, видна только маска.

`.env` создаётся установщиком. Обязателен в нём только пароль базы. Ключи (все поля описаны в `.env.example` и
`app/config.py`):

- база: `POSTGRES_HOST/PORT/DB/USER/PASSWORD` (пароль — только hex, он подставляется в URL);
- приложение: `APP_PORT`, `DEBUG`, `CORS_ORIGINS`, `BIND_HOST`;
- доступ: `OWNER_LOGIN/PASSWORD`, `OPERATOR_LOGIN/PASSWORD`, `MASTER_ACCOUNTS` (JSON с `staff_id`).
  Пароли, заведённые через мастер первого запуска, хранятся хешем PBKDF2 в базе;
- YCLIENTS: `YCLIENTS_PARTNER_TOKEN`, `YCLIENTS_COMPANY_ID`, `YCLIENTS_USER_TOKEN`, `YCLIENTS_OLD_*` (сверка со старым аккаунтом);
- выгрузка: `SYNC_INTERVAL_MINUTES` (60), `SYNC_WINDOW_DAYS` (90), `SYNC_WINDOW_AHEAD_DAYS` (60), `SYNC_TIMEOUT_MINUTES` (30), `CACHE_TTL_SECONDS`;
- Telegram: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`; почта: `MAIL_*`; hub: `HUB_URL`, `HUB_TOKEN`;
- салон: `BARBER_PAYROLL_RULES` (кто мастер и как считается ЗП), `TIMEZONE`, рабочие часы, шаг слотов, `OUTPUT_DIR`, `FONTS_DIR`.

**Никогда не кладите настоящий `.env` в архив или репозиторий.** В одной из прошлых версий в `.env.example`
лежали боевые ключи.

## 8. Сборка и выпуск

### Номер версии
`APP_VERSION` в `backend/app/main.py`. Номер виден на `/health` и в плашке «Пульт vX» в правом нижнем углу
(`Версия.tsx`). Его же ждёт `check.ps1` установщика. Перед выпуском поднимите номер и дополните «Что нового»
в `local/package/README.txt`.

### Пакет обновления
```
python3 scripts/build_package.py 9.26.0 /путь/куда
```
Что делает скрипт:
1. Выполняет `npm ci` (если нужно) и `npm run build` во `frontend/`.
2. Копирует репозиторий в `app/`, кроме `.git`, `node_modules`, `.venv`, кэшей, `static`, `output` и `hub`.
   Папка `frontend/dist` в копию попадает.
3. Проверяет: обязательные файлы на месте, число миграций совпадает с репозиторием, в `.bat` только ASCII и CRLF,
   у `.sh` и `.command` перевод строки LF и права 755.
4. Кладёт в корень файлы из `local/package/`.
5. Упаковывает в ZIP через Python `zipfile`, с флагом UTF-8 у русских имён. Утилиту `zip` не используйте:
   в Проводнике русские имена превращаются в кракозябры.
6. Если в системе есть `makensis`, собирает `Установка-Пульт-X.exe` из `local/installer/update.nsi`
   (amd64-unicode, MUI2, русский интерфейс).

На выходе: `Rubl-Director-X.zip` (один для Windows и Мака) и `Установка-Пульт-X.exe` (Windows).

Правила, выученные на инцидентах:
- в `.bat` только ASCII; русский текст в cmd ломается, сообщения пишите в README;
- в именах файлов проекта не должно быть «й» и «ё»: macOS раскладывает их в NFD, и `import` перестаёт находить файл;
- пакет собирается только этим скриптом, а не копированием вручную (в 9.22.4–9.22.5 так потерялись миграции).

### Установка и обновление у салона
- **Windows.** Установка лежит в `%LOCALAPPDATA%\RublDirector`: `app\` — код, `app\.env` — настройки,
  `app\local` — compose, `log\bootstrap.log` — журнал.
  - Обновление: `Установка-Пульт-X.exe`. Он копирует файлы в `app\`, запускает `bootstrap.ps1 -Mode install`
    (сборка образа и запуск), затем `check.ps1` ждёт `/health` с нужной версией.
    Коды bootstrap: 0 — готово, 20 — ждёт первичной настройки, 13 — нет Docker, 12 — не поднялся, 1 — исключение.
  - Запасной путь: распаковать ZIP и запустить `UPDATE.bat`.
  - Авария со схемой базы: `FIX-DB.bat` (`fix_db.py` проверяет и докатывает колонки).
  - Первичная установка на новый компьютер: нужен `bootstrap.ps1` из `local/installer/first-install/`
    (он ставит Docker, создаёт `.env`, регистрирует автозапуск). Исходник первичного установщика `.nsi` утерян,
    восстановлены только скрипты. Обновляющий `update.nsi` требует, чтобы `bootstrap.ps1` уже лежал в папке.
- **Mac владельца.** Установка лежит в `~/rubl-director`. Обновление: распаковать ZIP (`ditto -x -k`) и перетащить
  `UPDATE.command` в Терминал, либо открыть его двойным щелчком. Скрипт копирует файлы и вызывает `local/start.sh`.
  Владелец просил этот путь не менять. В `local/installer/mac-app/` лежит старый лаунчер `.app` (9.6),
  он ставил в `~/Library/Application Support/РублЪ Директор`; сейчас не используется.

Папка установки и имя проекта docker compose — часть данных. Если их сменить, база откроется с другим `.env`
(инцидент 30.09, `docs/history/04_...`).

## 9. Разработка у себя

```bash
# backend: тесты идут без сети и без Postgres (aiosqlite, фиктивные ключи в tests/conftest.py)
cd backend
uv sync
uv run pytest -q          # 644 теста
uv run ruff check .

# запуск против настоящей базы
cp ../.env.example ../.env   # заполнить POSTGRES_*, логины
uv run alembic upgrade head
uv run uvicorn app.main:app --reload --port 8000

# frontend: dev-сервер на :3000, /api проксируется на :8000
cd frontend
npm ci
npm run dev
npm run build             # tsc -b && vite build, обязателен перед сборкой пакета

# всё в Docker, как у салона
cd local && docker compose up -d --build
```

Соглашения:
- в коде много русских идентификаторов (`вся_база`, `ссылка_yclients`). Это осознанный стиль проекта, продолжайте его;
- комментарий объясняет «почему», а не «что»: почти у каждого решения в коде записана причина или инцидент;
- новая бизнес-функция приходит с тестом; правило о персональных данных — с тестом на состав выгрузки;
- e2e-проверка интерфейса делалась Playwright против собранного фронтенда и тестового Postgres. Отдельного набора
  e2e в репозитории нет.

| «YCLIENTS отказал (403): Нет прав на управление филиалом 2036703» / «Недостаточно прав» на всех шагах | пользователь, на которого выдан user token, больше не имеет прав в филиале: удалён, урезаны права или отключена интеграция. ## 12. Как владелец ведёт работу

- Сначала собираются замечания, выпуск — **только по команде** владельца.
- Владелец не работает в терминале на Windows: всё должно запускаться двойным щелчком (exe или bat).
  На Маке обновление через Терминал его устраивает.
- Версия всегда видна в углу экрана, и по ней проверяется, доехало ли обновление.
- Любые выгрузки и файлы, которые уходят с компьютера, — без имён и телефонов клиентов, только ID YCLIENTS.

## 13. Известные проблемы и бэклог

Открыто сейчас:
1. **YCLIENTS 403 у салона с 30.10** — права пользователя токена (§10, первая строка).

6. Выбор администратора на экране без пароля, а по нажатиям считаются деньги.

8. Исходник первичного установщика Windows (.nsi) утерян; обновляющий установщик полагается на уже стоящий `bootstrap.ps1`.
