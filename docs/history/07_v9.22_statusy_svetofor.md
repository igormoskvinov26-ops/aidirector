# Пульт 9.22.0 — скрипты по веткам, статусы, теги-стикеры, светофор

Собрано 16.10.2026 по пакету задач Игоря, 624 теста проходят. Продолжение
9.21.0 (теги, перезвон, вкладка «Обзвоны»).

## Скрипты: дерево разговора вместо одного текста

Регламент возврата из файла владельца («СКРИПТ ВОЗВРАТА КЛИЕНТОВ») заведён в
код как варианты группы «Потерянные»: `start` (начало), семь веток по причине
ухода — `quality`, `price`, `time`, `moved`, `other_barber`, `conflict`,
`just_long` — и `finish` (завершение с предложением записи). Сообщение для
тех, кто не ответил, лежит в `message` варианта `start`. У каждой ветки есть
`hint` — что администратору сделать дальше (зафиксировать детали, передать
руководителю, не давить на запись).

У остальных групп по два-три варианта: «Коротко», «Через мастера»,
«С заботой», у «Перезвонить» — «Коротко» и «По договорённости».

В карточке варианты переключаются чипами, в API задача отдаёт список
`scripts[{variant,title,hint,phone,message}]`. Приоритет прежний: варианты
тега идут впереди вариантов группы. Подстановки: `{имя}`, `{мастер}`,
`{услуга}`, `{дней_без_визита}`, новая `{админ}`.

Страница Настройки → «Скрипты обзвона» перестроена: разделы выбираются
кнопками, внутри список вариантов с названием, подсказкой и двумя полями;
`+ Добавить вариант` заводит свой, корзина удаляет. Пустое поле = текст из
регламента.

## Статусы контакта

`clients.call_status` + расширенный `record_outcome`. Пять статусов:
`booked` (Записан), `callback` (Перезвонить), `no_booking` (Без записи),
`no_answer` (Не дозвонились), `do_not_call` (Не звонить).

Правила, заданные владельцем:
- «Не дозвонились» — сервер сам ставит следующий звонок на завтра и пишет
  причину «не дозвонились»; дата последнего разговора не двигается, разговора
  не было;
- «Перезвонить» без даты не принимается: сервер возвращает 400, кнопка в
  интерфейсе неактивна, пока дата не выбрана в блоке «Перезвонить»;
- «Не звонить» ставит `do_not_call` и снимает плановую дату;
- «Записан» и «Без записи» снимают плановую дату.

## Карточка клиента

- Строка «последний звонок: Екатерина, 11.10.2026» — видно, чей комментарий.
- Крупное число дней со звонка: зелёное до 14 дней, жёлтое до 30, красное
  дальше.
- Светофор лояльности (`clients.loyalty`): зелёная / жёлтая / красная лампа,
  ставит администратор по тону разговора, горит постоянно; повторное нажатие
  той же лампы гасит.
- Теги — строка цветных стикеров: клик вешает или снимает, `+ тег` заводит
  новый. Создание тега разрешено администратору (раньше было только
  управляющему), удаление тега по-прежнему за управляющим: оно снимает тег со
  всех клиентов разом. Цвет новому тегу назначается из палитры автоматически.

## Вкладка «Позвонить сегодня»

Пятая вкладка раздела «Клиенты»: только те, у кого плановая дата наступила
или просрочена. Закрыта до выбора администратора, как и «Администратор».

## Хранение на сервере

`hub.py` выгружает два новых документа:
- `client_state` — по `yclients_id`: плановая дата, статус, светофор,
  `do_not_call`, коды тегов. Состав полей закрыт константой `ПОЛЯ_СОСТОЯНИЯ`
  и проверяется тестом: имени, телефона и текста договорённости там нет.
- `client_tags` — справочник тегов (код, название, цвет, флаги).
Пустые документы не отправляются. При получении состояние раскладывается по
локальным клиентам, найденным по `yclients_id`; незнакомые строки
игнорируются.

## Остаётся открытым

1. Причина ухода из регламента (качество / цена / запись / расположение /
   другой мастер / сервис / личное) пока не отдельное поле — администратор
   пишет её в комментарий. Если нужна аналитика «почему уходят», это
   следующий шаг: выпадающий список на карточке и разрез во вкладке
   «Обзвоны».
2. KPI из регламента (контактность, доля выяснённых причин, решённые
   проблемы) — считать после того, как появится поле причины.
3. Пункты из плана 9.21: редизайн остальных страниц, неделя на стыке
   месяцев, телефонная вёрстка, общая учётка владельца, почта (IMAP),
   формула премии за возвращённых, фильтр «акционные» для праздников.
