## 1. Почему Мак отказывался открывать программу

Окно «Apple could not verify "РублЪ Директор" is free of malware» — не
поломка сборки. У приложения нет подписи Apple: она стоит 99 $ в год и
выдаётся только по аккаунту разработчика. Без неё macOS вешает на всё
скачанное метку карантина и отказывается запускать.

В macOS 15 старый обход (правый щелчок → «Открыть») убрали, поэтому в пакет
добавлен файл **`Установка.command`**: он снимает метку карантина со всей
папки, кладёт программу в «Программы» и запускает её.

Если macOS блокирует и сам этот файл — два пути, оба описаны в
«ПРОЧТИ МЕНЯ.txt» внутри архива:

- **Терминал** (работает всегда): набрать `bash ` с пробелом, перетащить
  `Установка.command` в окно Терминала, Enter. Терминал, запуская скрипт
  напрямую, карантин не проверяет.
- **Системные настройки** → «Конфиденциальность и безопасность» → внизу
  кнопка «Открыть всё равно».

Уже установленную копию можно вылечить одной строкой:

```
xattr -dr com.apple.quarantine "/Applications/РублЪ Директор.app"
```

Полностью убрать это окно можно только подписью Apple Developer ID. Если
такой аккаунт появится — сборка станет notarized, и вопрос снимется.

## 2. Ключи настраиваются в самом Директоре

Раньше свежая установка упиралась в `.env`: чтобы открыть Директора, нужен
пароль из файла, а чтобы его туда вписать — доступ к файлу на сервере.
Теперь этого шага нет.

**Первый запуск.** Директор поднимается без всяких ключей и показывает мастер
настройки. Он спрашивает короткий код (печатается в окне установки и лежит в
`output/код-настройки.txt`), потом владелец придумывает себе логин и пароль —
и попадает в программу. Код после этого перестаёт действовать, файлы с ним
удаляются.

**Раздел «Настройки → Интеграции»** (виден только владельцу):

- YCLIENTS и Telegram с отдельными статусами: настроено / настроено частично /
  требуется настройка / ошибка подключения;
- кнопка «Загрузить .env» — файл сначала показывается предпросмотром
  (что найдено, чего не хватает, что не используется) и применяется только
  после подтверждения;
- ручное заполнение полей;
- «Проверить подключение» по каждой интеграции и «Тестовое сообщение» для
  Telegram (само не отправляется никогда);
- «Убрать / сбросить» по каждому полю;
- журнал изменений: кто, когда, какой параметр. Сами значения не хранятся.

**Правка одного поля не трогает соседнее.** Чтобы исправить неверный chat_id,
достаточно вписать новый чат и оставить поле токена пустым: пустое означает
«не менять». Перезапуск не нужен, значение действует сразу.

**Без Telegram аналитика работает.** Не настроенная интеграция гасит только
свои функции, а не всю программу.

### Приоритет источников

```
переменная окружения сервера  >  настройка через веб  >  файл .env  >  пусто
```

Заданное инфраструктурой показывается с пометкой «задано на сервере» и
доступно только чтению: иначе настройка «применялась» бы ровно до
перезапуска. Файл `.env` при этом не перезаписывается никогда — управляемые
значения лежат в базе, и сценарий «`.env` только для чтения» работает сам
собой.

### Что с безопасностью

- Секреты наружу не отдаются: только «заполнено/не заполнено» и маска
  `••••••••7Kp2`. Маска обратно как значение не принимается.
- Пароль владельца, заведённый через мастер, хранится хешем PBKDF2, а не
  открытым текстом, как в `.env`.
- Права проверяются на сервере: администратор и мастера получают 403 и на
  чтение, и на запись настроек.
- Загруженный файл не выполняется, в журнал не пишется, чужие ключи не
  применяются.

## 3. Что ещё изменилось

- `.env` создаётся автоматически при установке, пароль базы генерируется сам.
  Заполнять файл руками больше не нужно ни на Windows, ни на Маке.
- Незаполненные заготовки вида `КЛЮЧ=<...>` больше не останавливают запуск —
  просто убираются.
- Сторис в Telegram теперь уходят тому же боту, что и отчёты смены: раньше
  они читали только `.env` и после настройки через форму продолжали слать
  старому боту.
- Пока YCLIENTS не настроен, выгрузка не идёт и не пишет каждый час
  неудачный прогон в журнал — ошибки от этого перестают тонуть.
- Ненастроенная интеграция отвечает 503 с понятным текстом, а не 500.

## 4. Почему 9.3 не собиралась на Маке — и что сделано

`npm run build` падал внутри Docker с `Cannot find module './НастройкиPage'`,
хотя файл лежал на месте.

Причина — в букве **«й»**. macOS при распаковке архива записывает такое имя
в разложенном виде: «й» становится «и» плюс отдельный значок сверху, то есть
двумя символами вместо одного. Linux внутри Docker ничего не раскладывает, и
строка `import` в коде перестаёт совпадать с именем файла на диске.

Это никогда не всплывало раньше потому, что в проекте уже были русские имена
файлов — `тема.ts`, `мастера.tsx`, `сборка.d.ts` — но ни в одном из них нет
ни «й», ни «ё». Только эти две буквы раскладываются.

Сделано:

1. Два новых компонента переименованы латиницей: `SettingsPage.tsx` и
   `SetupWizard.tsx`. Русские имена внутри проекта остаются — запрет
   касается только «й» и «ё».
2. В `installer/build.sh` добавлена проверка: если в пакет попадает файл или
   папка, чьё имя меняется при разложении Unicode, сборка останавливается с
   объяснением. Проверено на подсадном файле — останавливает.
3. Отказ воспроизведён (переименованием файлов в разложенный вид сборка
   ломается тем же кодом выхода 2) и проверено, что после исправления та же
   имитация не меняет ни одного имени, а сборка проходит.

**Правило на будущее:** в именах файлов проекта не должно быть «й» и «ё».
К содержимому файлов это не относится.
