## 2. Расхождения в текущем коде (то, от чего предостерегает §30)

1. **«Потерянный» считается тремя разными способами.**
   - Пульс и баланс базы: 61-й день без визита (`LOST_AFTER_DAYS = 60`, потерян на `+61`).
   - Отчёт смены: `стали_потерянными` берёт последний визит ровно `сегодня − 60` — это 60-й день, на день раньше.
   - **Очередь обзвона**: группа «Потерянные» строится по личному ритму клиента (`compute_segment`: r > 2 интервалов) или, при нестабильном ритме, после **120** дней. Клиент с ритмом 20 дней попадает в «Потерянные» на 41-й день, клиент с одним визитом — только на 121-й.
   - Флаг `was_lost` (основа премии) ставится по группе очереди, а не по правилу 61 дня. Без исправления премия будет считаться не по определению из ТЗ.
2. **Формула пульса разная.** Баланс базы: новые + вернулись − потеряны. Сообщение о закрытии смены: новые − потеряны (без вернувшихся).
3. **Будущая запись задним числом не учитывается** (`base_flow` прямо это оговаривает): история пульса — оценка. Это и есть причина, по которой ТЗ требует дневные снимки и эпизоды: их надо писать каждый день начиная с запуска.
4. **История визитов неглубокая.** Синхронизация берёт окно 90 дней назад / 60 вперёд и копит строки с момента установки. «Впервые в жизни», «число прошлых визитов» и «мастер первого визита» для старых клиентов по таблице визитов определить нельзя. Нужна разовая загрузка полной истории записей из YCLIENTS (за все годы работы салона).
5. **Удалённые записи.** Если запись удалили в YCLIENTS после синхронизации, локальная строка может остаться «запланирована» и не давать клиенту стать потерянным. Проверить (§32 п.10).
6. **Админ выбирается на экране без пароля** (`admin_staff_id`). Для расчёта денег слабое место: любой может отметить звонок от имени другого.

## 3. Неясности и противоречия в самом ТЗ

1. **«Новый» в пульсе.** §3: «впервые записавшиеся». §1.1 и статистика мастеров — по первому выполненному визиту. Сейчас пульс считает по визиту. По записи: неявка новичка уже засчитана в +1 и не откатится.
2. **Отменённая запись после «вернулся в запись».** День уже сохранён с +1. Переписывать прошлые снимки или фиксировать день на закрытии? ТЗ не говорит.
3. **Когда становится потерянным клиент, у которого отменили запись на 75-й день.** По §1.2 — в день отмены. Это нужно явно зафиксировать: «стал потерянным = первый день, когда выполнены оба условия».
4. **Удержание мастера, §12.** «Вернулся в течение рассматриваемого периода» не определено. Если второй визит на 75-й день — это «не удержан» или «вернулся»? И куда относить клиента, у которого на 60-й день есть запись, но ещё нет визита? Нужно фиксированное окно (например, второй визит в течение 60 дней от первого), иначе проценты будут «плыть».
5. **§14 «3 / 7»** — за какой период: 30 дней, месяц, всё время?
6. **Защита от двойной оплаты, §27.** Ключ «запись + эпизод + админ» допускает две выплаты за один визит, если двое админов звонили одному клиенту. Для «одна выплата за возврат» уникальность должна быть по эпизоду. Кому платить — админу, чьё нажатие сопоставлено с записью (как уже делает `match_attempts`).
7. **Средний пульс за 30 дней (§8)** появится только через 30 дней после запуска снимков. До этого — оценка по истории с пометкой.

## 4. Решения, нужные от Игоря до начала работ

1. Группа «Потерянные» в очереди обзвона — перевести на правило 61 дня (остальные группы «пора / риск / задерживаются» остаются по ритму)? Рекомендую да — иначе премия и пульс считают разных людей.
2. «Новый» в пульсе — по первой записи или по первому выполненному визиту? Рекомендую по визиту.
3. Удержание мастера — окно для второго визита 60 дней от первого? Рекомендую да; запись без визита на 60-й день — «ещё не созрел», в расчёт не берём до визита или отмены.
4. Прошлые дни пульса фиксируются на закрытии дня и не переписываются; «вернулось впоследствии» считаем по фактическим визитам. Согласен?
5. Одна выплата за один возврат (эпизод), платим админу, чьё «Запись» сопоставлено с записью в YCLIENTS. Согласен?
6. ~~Ставка премии~~ — **решено 21.10:** ставка не фиксируется в коде, задаёт её Владелец в режиме владельца. Пока не задана — количество выполненных возвратов считается и показывается, сумма премии не выводится.
7. Нужны ли отдельные логины для каждого администратора (раз по нажатиям считаются деньги)?
8. Период для показателя «3 / 7» по мастерам.

## 5. План работ по этапам

**Этап 0. Единые определения и данные (без него остальное разъедется).**
- Один модуль жизненного цикла (`lifecycle.py`): новый, потерянный (61 день + нет будущей записи), вернулся в запись, вернулся фактически. Его используют пульс, смена, очередь, админы, мастера.
- Исправить `shift.стали_потерянными` (60 → 61 день) и формулу пульса в отчёте смены.
- Разовая загрузка полной истории записей YCLIENTS; проверка удалённых записей.
- Миграция 0017: таблица `lost_episodes`; поля в `contact_attempts`: `episode_id`, `segment_at_call`, `completed_at`.

**Этап 1. Эпизоды и дневные снимки.**
- Ежедневный проход (при синхронизации и открытии смены): открыть эпизоды у ставших потерянными, отметить «вернулся в запись» / «вернулся фактически» / отмену, канал (обзвон — есть сопоставленный звонок; онлайн — `api_id`; иначе — другое).
- Таблица `daily_pulse_snapshots`: дата, числа и списки ID (новые, вернулись, потеряны), пульс. Миграция 0018.

**Этап 2. Страница «Пульс базы».**
- Спидометр сегодня с кликабельной расшифровкой; история 30 дней с нулевой линией, клик по дню → кто потерян, сколько вернулось потом, %; средний пульс за 30 дней.

**Этап 3. Открытие смены.**
- Живой прогноз: под риском сегодня, возвращены в запись, осталось вернуть, «до нуля нужно вернуть N»; список кликабельный, клиент исчезает после записи.

**Этап 4. Воронки администраторов.**
- Стадия «выполнено» без лишних запросов к YCLIENTS: `contact_attempts.yclients_record_id` = `visits.yclients_id` со статусом «выполнен» — сверка локальная.
- Сверка при открытии смены, закрытии и кнопке «Синхронизировать»; без дублей.
- Страница «Администраторы»: фильтры (сегодня / неделя / месяц / период / расчётный месяц), число обзвонов, две воронки «Запись → Подтверждено → Выполнено» и «Возврат потерянных», конверсии; KPI «новые клиенты, записанные админом» по `created_user_id`.

**Этап 5. Премия.**
- Таблица `bonus_accruals`, уникальность по эпизоду; месяц — по дате выполненного визита; закрытый месяц замораживается (как месячный отчёт).
- Ставка за выполненный возврат — поле в режиме Владельца (видно и меняется только под ролью owner). Пустая ставка = суммы нет, есть только количество возвратов. Начисление хранит ставку на момент расчёта, чтобы смена ставки не переписывала прошлые месяцы.

**Этап 6. Удержание по мастерам.**
- Только новички «впервые в жизни», созревшие (60+ дней от первого визита); три исхода = 100%; три мини-спидометра и абсолютные числа; «не удержаны после 1-го визита / всего потеряно».

Все новые таблицы — только в локальной базе салона: имена и телефоны на сервер не уходят. Наружу при необходимости — только суммы премий и имена сотрудников.
