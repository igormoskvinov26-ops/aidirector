# РублЪ — AI Director

**AI-управленческая система для барбершопа «РублЪ».** Версия 2.0.

## Стек

| Слой | Технологии |
|------|-----------|
| Backend | Python 3.11+, FastAPI, SQLAlchemy 2, Alembic, httpx, loguru |
| Database | PostgreSQL 16 |
| Frontend | React 19, Vite, TypeScript, Tailwind CSS, Recharts |
| Отчёты | Внутренний расчёт по правилам, без внешнего API |
| Data | YCLIENTS API |

---

## Быстрый старт

```bash
cp .env.example .env
# Заполнить .env. Пароли сгенерировать, не придумывать:
#   openssl rand -base64 24   → POSTGRES_PASSWORD
#   openssl rand -base64 18   → OWNER_PASSWORD
./start.sh
```

Приложение откажется стартовать, если пароли пустые, короче 12 символов или
совпадают с известными слабыми значениями. Это сделано специально.

Дашборд: http://localhost:3000

## Проверка перед деплоем

```bash
./scripts/check-keys.sh
```

Стучится в YCLIENTS и Telegram ключами из `.env`, проверяет права на
файл, длину паролей и A-запись домена. Ключи не печатает. Возвращает код 1,
пока есть проблемы.

## Деплой

```bash
DOMAIN=director.rublbarber.ru ./deploy.sh
```

Скрипт разворачивает PostgreSQL, накатывает миграции, поднимает сервис от
пользователя `rubl`, ставит nginx и получает сертификат Let's Encrypt.
Приложение слушает только `127.0.0.1:8000`; наружу открыт единственный порт 443.

Деплой без домена невозможен: сертификат на голый IP не выдаётся.

## Что изменилось в 2.0

### Безопасность
- Боевые ключи убраны из `.env.example` — там только заглушки. **Все ключи
  прошлой версии считаются скомпрометированными и требуют перевыпуска.**
- Пароли не имеют значений по умолчанию; известные слабые значения отвергаются
  на старте.
- `CORS` больше не `*` с `allow_credentials` — список доменов задаётся в `.env`.
- Сервис работает от непривилегированного пользователя под systemd-песочницей.
- Настоящий TLS вместо самоподписанного сертификата.
- Пароль не печатается в консоль при деплое.

### Работоспособность
- PostgreSQL наконец разворачивается при деплое. Раньше его не было, приложение
  проглатывало ошибку подключения и молча отдавало 500 в разделах «Клиентская
  база», «Финансы» и «AI-отчёты».
- Схема переведена под Alembic. Оговорка: базовая ревизия `0001_initial` внутри
  вызывает `create_all` — это снимок текущей схемы, а не настоящая миграция.
  Следующие изменения моделей обязаны оформляться отдельными ревизиями.
- Ошибка подключения к базе теперь останавливает старт, а не пишется в лог.

### Скорость
- Ответы YCLIENTS кэшируются (TTL из `.env`), параллельные запросы разделяют
  один поход в API вместо N одинаковых.
- `get_all_records` требует границы дат и отвергает диапазоны шире 400 дней.
  Раньше каждый запрос слотов выкачивал всю историю записей.
- Фоновая синхронизация работает в окне `SYNC_WINDOW_DAYS` (по умолчанию 90).
- Фронтенд разбит на чанки: код приложения 48 КБ отдельно от `react` (179 КБ) и
  `charts` (404 КБ). Суммарный объём JS прежний — выигрыш в кешировании между
  деплоями, а не в размере загрузки.

### Логика
- **Свободные окна считаются заново.** Раньше «работающим сегодня» считался
  мастер, у которого уже есть хотя бы одна запись. Мастер с полностью пустым
  днём выпадал из выдачи — то есть именно тот, чьи окна нужнее всего
  рекламировать. Теперь график берётся из YCLIENTS, а при недоступности
  расписания показываются все активные мастера с пометкой `source`.
- Запись занимает всю свою длительность, а не только время начала. Часовая
  стрижка больше не оставляет следующие полчаса «свободными».
- В выдаче первым идёт самый свободный мастер.
- Четыре копии расчёта слотов заменены на `app/services/slots.py`.
- `main.py` сократился с 522 строк до 160: только сборка приложения.

### Прочее
- Исправлено `31` число в каждом месяце — отчёты за февраль, апрель, июнь,
  сентябрь и ноябрь запрашивались с несуществующей датой.
- Статика пересобрана: раньше на сервере лежала сборка от 12 августа.
- `playwright` (не использовался) и `html2canvas` (не импортировался) удалены.
- Путь для сторис берётся из конфига, а не прибит к `/opt/rubl-director`.
- Шрифты сторис ищутся в `assets/fonts` — см. README там.
- 16 тестов на исправленные баги: `cd backend && uv run pytest`.

## Перевыпуск ключей

См. `ROTATION.md` — таблица «где какой ключ выпускается заново» и порядок замены.

Сверить старый `.env` с новым, не выписывая значения:

```bash
./scripts/compare-env.sh /путь/к/старому/.env .env
```

Скрипт печатает отпечатки sha256 и вердикт по каждому секрету.

## Известные проблемы

Сборка прошла внешний аудит 10–11.09.2026. Найдено: один блокер безопасности
(боевые ключи в публичном репозитории — устранено, см. `ROTATION.md`) и ряд
дефектов в слое данных, из-за которых часть цифр на дашборде недостоверна.
Ключевые, до исправления которых отчётам доверять нельзя:

- Отмены и неявки не сохраняются в базу: нормализатор сводит все незавершённые
  статусы в `scheduled`, поэтому `cancellation_pct` всегда 0.
- На дашборде `visit_attendance == 2` трактуется как отмена, хотя это
  подтверждение записи.
- KPI в базе не пересчитываются фоном, поэтому отчёт получает пустой набор.
- Дашборд существует в двух независимых реализациях с разными формулами.
- Время считается в трёх разных конвенциях; бизнес-датой должен быть
  Europe/Moscow.
- Роли существуют только в интерфейсе; API их не проверяет.

Действующее ТЗ — перенос в Yandex Cloud (serverless, без постоянной SQL-базы).
Этот код остаётся эталоном при переносе расчётов, а не целевой архитектурой.
